How alerts are generated

Critical: level below 20%. High: hourly energy intensity above 0.85 kWh/kL. Watch: level below 30%. Critical takes precedence. Consecutive faulty readings are grouped into one current investigation per site. These are demonstration rules, not validated operational limits.

BUILT BY CHOSHITHA ANISETTI

A portfolio project with a connected story.

FlowGuard brings together skills developed through a Master of IT (Data Analytics), Python and SQL internship work, a SAPS document assistant, and a university water tank cybersecurity assessment. These fictional sites do not represent a university or employer system.

Data engineering

Seeded generation, validation, reproducible ETL, relational constraints.

SQL analytics

Joins, grouped metrics, safe division and ROW_NUMBER for latest observations.

Investigation

Site-level drilldowns, explicit thresholds and traceable runbook references.

Product thinking

Accessible controls, CSV exports, responsive interface and honest limitations.

Included in version 1

Working operations dashboard, investigation desk, authored demonstration runbooks, quality report, Python pipeline, SQLite database, SQL views, checks and GitHub Pages workflow.

Next development steps

Evaluate real public data sources, build a tested forecasting baseline, and add document retrieval with citations. This version contains no trained model, live sensor connection or generative AI assistant.
